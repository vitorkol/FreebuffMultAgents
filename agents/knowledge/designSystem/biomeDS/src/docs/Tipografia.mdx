<SectionHeader title="Três níveis de uso tipográfico" description="Do padrão mais simples ao override avançado (mesmo contrato visual em todas as linhas)." />

<DocsCallout type="danger" title="IMPORTANTE">
  O HTML define semântica e acessibilidade. Para qualquer árvore (semântica ou composicional), aplique as classes semânticas <strong>text-*</strong> do Biome para garantir o nível visual correto.
</DocsCallout>

### 1. HTML semântico + classe explícita (padrão)

```html
<h1 className="text-display-xl text-foreground">Título de página</h1>
<p className="text-body-m text-foreground">Texto corrido da interface.</p>
<small className="text-meta-xs text-muted-foreground">Rubrica ou nota menor</small>
```

- O elemento semântico continua obrigatório para acessibilidade e estrutura.
- O nível visual deve ser aplicado com classes da escala tipográfica do Biome.

---

### 2. text-* em elementos não semânticos (uso controlado)

```tsx
<span className="text-heading-l text-foreground">
  Título dentro de slot/árvore sem marcador semântico adequado
</span>
```

- Adequado a **Radix**, **slots** e **composição** quando não é possível usar diretamente `h1`–`h6`, `p`, `label`, etc.
- Mantenha semântica com HTML sempre que possível; use `text-*` como fallback técnico.

---

### 3. Override avançado (com classes do contrato)

```tsx
<p className="text-body-s text-muted-foreground">Texto secundário menor</p>
<h4 className="text-heading-m text-foreground">Título menor em contexto denso</h4>
```

- Sobrescritas seguem exclusivamente a escala nomeada do DS.
- Para cor, use tokens semânticos sem sair do contrato tipográfico.

---

<SectionHeader title="Regras de Uso" />

<DoRule>Use elementos <code>h1</code>–<code>h6</code>, <code>p</code>, <code>small</code> e <code>label</code> quando couber, aplicando explicitamente a classe de escala do Biome para cada caso.</DoRule>
<DoRule>Fora de elementos semânticos, use apenas os nomes de escala{' '}<code>{'text-meta-*'}</code>,{' '}<code>{'text-body-*'}</code>,{' '}<code>{'text-heading-*'}</code>,{' '}<code>{'text-display-*'}</code> — não <code>text-xl</code> genérico do Tailwind como se fosse o DS.</DoRule>
<DoRule>Use <code>pnpm governance:typography-contract</code> antes de PR em componentes que alterem JSX com parágrafos/títulos.</DoRule>
<DontRule>Não deixe níveis tipográficos sem declaração explícita em <code>{'h*'}</code>, <code>p</code> e <code>label</code>; aplique sempre classes tipográficas do DS.</DontRule>
<DontRule>Não use <code>font-display</code> (Poppins) em metadados pequenos; use roboto + escalas compactas ({' '}<code>{'text-meta-*'}</code>, <code>text-body-s</code>).</DontRule>
<DontRule>Mantenha uma única hierarquia: Figma Styles ↔ utility <code>{'.text-*'}</code> ↔ <code>{':root'}</code> (<code>typography.json</code>).</DontRule>
