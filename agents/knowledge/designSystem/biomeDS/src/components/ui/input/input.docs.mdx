# Input

Campo de texto **canônico** do Biome para produto: label opcional, texto auxiliar, validação inline e acessórios internos (ícones, `passwordToggle`, `endAction="clear"`). Substitui os antigos `InputText`, `SearchInput` e o input primitivo — use apenas este componente para entradas de uma linha.

`type="search"` aplica o estilo de busca nativo sem o botão cancel do WebKit; com `endAction="clear"`, o botão limpar só aparece quando há texto, alinhado ao padrão de busca.

<SectionHeader title="Acessibilidade" />

- **Associação de label** — A prop `label` renderiza um `<label>` vinculado ao input via `htmlFor`/`id`, garantindo que leitores de tela anunciem o nome do campo.
- **Mensagens de erro** — Com `hasError`, o texto auxiliar se torna mensagem de erro conectada via `aria-describedby` ao input.
- **Toggle de senha** — O botão de visibilidade possui `aria-label` dinâmico ("Mostrar senha" / "Ocultar senha") e `aria-pressed` atualizado, comunicando o estado corretamente.
- **Ação de limpar** — O botão de limpar possui `aria-label="Limpar campo"` e foca automaticamente o input após a ação.
- **Ícones decorativos** — Ícones de `startIcon` e `endIcon` recebem `aria-hidden="true"` automaticamente.

<SectionHeader title="API pública" />

- `startIcon` (`IconName`) — ícone Lucide à esquerda do campo.
- `endIcon` (`IconName`) — ícone Lucide à direita; oculto por `clear` ou `passwordToggle`.
- `passwordToggle` (`boolean`) — botão interno para alternar visibilidade da senha.
- `endAction` (`"clear"`) — ação interna no lado direito para limpar o campo.
- `onClear` (`() => void`) — callback ao clicar em limpar.
- `label` (`string`) — rótulo acima do campo.
- `helperText` (`string`) — texto auxiliar ou mensagem de erro.
- `hasError` (`boolean`) — ativa estado visual de erro e ARIA correspondente.
- `size` (`"sm" | "md" | "lg" | "xl"`) — escala de altura do campo.

<DocsCallout type="info" title="API declarativa">
  O Input não expõe slots para ReactNode arbitrário. O consumidor declara a intenção (por exemplo, <code>passwordToggle</code> ou <code>endAction="clear"</code>) e o design system decide internamente como renderizar, usando os próprios componentes Biome.
</DocsCallout>

<SectionHeader title="Boas práticas" />

<DoRule>Prefira sempre um label visível ou uma associação explícita via <code>aria-label</code> quando o layout não puder exibir rótulo.</DoRule>
<DoRule>Use helperText para comunicar expectativas de formato (por exemplo, "Mínimo 8 caracteres, letras e números").</DoRule>
<DoRule>Use passwordToggle em campos de senha para melhorar a usabilidade sem comprometer acessibilidade.</DoRule>
<DoRule>Use type="search" com startIcon="search" e endAction="clear" para busca com UX alinhada ao padrão de mercado.</DoRule>

<DontRule>Não passe componentes JSX diretamente como acessórios — use as props declarativas startIcon, endIcon, passwordToggle e endAction.</DontRule>
<DontRule>Não confie apenas em cor para indicar erro — a mensagem de texto no helperText fornece o contexto necessário.</DontRule>
