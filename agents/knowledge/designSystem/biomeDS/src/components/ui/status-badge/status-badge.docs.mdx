<SectionHeader title="Acessibilidade" />

<DocsCallout type="info">
  O ícone usa <code>aria-hidden="true"</code> — a informação de status é transmitida pelo <code>label</code> e pela cor, não apenas pelo ícone. O <strong>label textual é obrigatório</strong>.
</DocsCallout>

- `StatusBadge` renderiza um `<span>` — não é interativo. Se o status for clicável, envolva em um `<button>`.
- Em listas longas, adicione `aria-label` descritivo ao elemento pai.

<SectionHeader title="Boas Práticas" />

```tsx
// ✅ Use sempre o label do status real do sistema
<StatusBadge intent="success" label={attendance.statusProcesso} />

// ✅ Crie uma função de mapeamento centralizada
// utils/status.ts
export function getStatusIntent(status?: string): StatusIntent {
  if (!status) return 'neutral'
  const s = status.toLowerCase()
  if (['conclu', 'finaliz', 'encerrad'].some(k => s.includes(k))) return 'success'
  if (['cancel', 'arquiv'].some(k => s.includes(k)))              return 'destructive'
  if (['andamento', 'aguard'].some(k => s.includes(k)))           return 'warning'
  return 'info'
}

// ❌ Não use Badge raw com classes utilitárias soltas de status
<span className="rounded-full border px-2 py-1 text-label-s">
  Concluído
</span>

// ✅ Correto
<StatusBadge intent="success" label="Concluído" />
```
