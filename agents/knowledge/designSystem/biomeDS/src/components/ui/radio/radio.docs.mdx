# Radio / RadioGroup

Componentes de seleção única. `Radio` é o controle individual; `RadioGroup` gerencia um conjunto de `Radio` dentro de um `<fieldset>` semanticamente correto.

<SectionHeader title="Quando Usar" />

<DoRule>Para selecionar uma opção de um conjunto pequeno e fixo (2–6 opções visíveis simultaneamente).</DoRule>
<DoRule>Quando todas as opções precisam estar visíveis ao mesmo tempo para comparação.</DoRule>
<DoRule>Para perguntas de sim/não ou escolhas binárias.</DoRule>

<SectionHeader title="Quando Não Usar" />

<DontRule>Para selecionar múltiplas opções — use Checkbox.</DontRule>
<DontRule>Para listas longas (7+ opções) — use Select (dropdown).</DontRule>
<DontRule>Para ligar/desligar uma configuração binária — use Switch.</DontRule>

<SectionHeader title="Anatomia" />

- **Input nativo** — oculto visualmente (`sr-only`), preserva semântica e foco.
- **Indicador visual** — anel externo + ponto interno para estado selecionado.
- **Label** — texto clicável que ativa o `input`.
- **Helper text** — texto auxiliar ou mensagem de validação.

```tsx
<button

  onClick={() => setAttendantRating(option)}
```

**Depois (Biome):**
```tsx
<RadioGroup legend="Como você avalia o atendimento recebido? *" row>
  {ratingOptions.map(opt => (
    <Radio
      key={opt}
      name="rating"
      value={opt}
      label={ATTENDANT_RATING_LABELS[opt]}
      checked={rating === opt}
      onChange={() => setRating(opt)}
    />
  ))}
</RadioGroup>
```

<SectionHeader title="Acessibilidade" />

### Radio individual

- O input nativo `<input type="radio">` é preservado com `sr-only`, garantindo:
  - Navegação por teclado nativa do browser
  - Suporte completo a tecnologias assistivas
  - Grupos de rádio com `name` compartilhado gerenciam seleção exclusiva automaticamente
- O label usa `htmlFor` conectado ao `id` do input → clicar no label ativa o controle
- `aria-invalid` é definido quando `hasError` está ativo
- `aria-describedby` conecta o input ao `helperText`

### RadioGroup

- Usa `<fieldset>` + `<legend>` para agrupar controles relacionados semanticamente
- Leitores de tela anunciam: *"[legend]: [label da opção] — 1 de 4 rádios"*
- O erro do grupo usa `aria-describedby` no fieldset

<SectionHeader title="Boas Práticas" />

**✅ Sempre use `RadioGroup` para dois ou mais rádios relacionados**
```tsx
// Evite rádios soltos sem fieldset
<RadioGroup legend="Tipo de solicitação">
  <Radio name="tipo" value="denuncia" label="Denúncia" />
  <Radio name="tipo" value="consulta" label="Consulta" />
</RadioGroup>
```

**✅ Use o mesmo `name` para todos os rádios de um grupo**

Isso garante que o browser selecione apenas um por vez e que o valor correto seja enviado no `<form>`.

**✅ Integre com react-hook-form via register**
```tsx
const { register } = useForm()
// ...
<RadioGroup legend="Avaliação *">
  {options.map(opt => (
    <Radio key={opt} value={opt} label={opt} {...register('rating')} />
  ))}
</RadioGroup>
```

<SectionHeader title="Anti-Padrões" />

**❌ Não use `<button>` para simular seleção exclusiva**
```tsx
// Errado — botões com toggle de borda não são semânticos
<button onClick={() => setSelected("A")} className={selected === "A" ? "border-brand-green" : ""}>
  Opção A
</button>

// Correto
<Radio name="opcao" value="A" label="Opção A"
  checked={selected === "A"} onChange={() => setSelected("A")} />
```

**❌ Não use Radio para 7+ opções**
```tsx
// Errado — muitas opções em rádio são difíceis de escanear
<RadioGroup legend="Estado *">
  {estadosBrasileiros.map(e => <Radio key={e} ... />)}
</RadioGroup>

// Correto
<Select label="Estado *" options={estadosBrasileiros} />
```
